# Agent Note：保持桌面 CLI 身份跨命令租约稳定

Status: implemented

[English](2026-10-21-stable-desktop-cli-identity.md) | 中文

## 问题

上游 CLI 用桌面桥接密钥绑定已保存的调用。Main 有意为每次命令生成新密钥，因此后续确认可能拒绝同一已登录账号。只更新生产线技能而不更新内置 CLI，也会留下版本不兼容。

## 决策

Main 为代理描述文件增加身份摘要：对用途域、所选站点、环境和当前凭据计算 SHA-256。摘要不能用于授权。每次命令的能力仍随机生成，受作用域、有效期和独立撤销约束。描述文件 IPC 解析器要求该摘要。

应用固定官方 CLI 1.2.16 归档，在资源准备阶段对两个模块应用显式补丁。CLI 描述文件校验要求身份摘要，调用身份由此计算，不再依赖命令授权能力。重新授权或凭据轮换会使旧调用身份失效。应用内置已校验的公开生产线技能 1.2.9，不改写用户或项目文件。技能的单模块适配补丁保留桌面托管身份，要求私有描述文件，并保持独立登录和连接器行为。Main 提供明确的 CLI 与 既有 CLI 状态路径，适配器不再将 shell 启动器误认为 npm 包或回退到全局安装。

此决策补充[浏览器账号决策](../architecture/2026-09-08-browser-account-authorization.zh.md)。其 Main 所有权、私有描述文件、退出登录和传输规则继续有效，没有完整取代既有记录。

## 考虑过的替代方案

复用命令密钥会扩大命令生命周期并削弱撤销；忽略身份比较会允许其他凭据确认；只升级全局 CLI 不会改变应用固定的启动器；隐式 CLI 回退会掩盖不兼容。

## 影响

上游 CLI 变更时必须重新审核补丁。基于临时密钥生成的既有确认需要重新报价并明确确认，不自动重放或迁移付费操作。应用启动校验固定归档与补丁身份。

## 验证

真实 CLI 与代理测试证明：独立命令授权能力对应相同调用身份，重新授权后身份变化，无效描述文件在 API 请求前拒绝，环境凭据不能替代托管授权。资源测试验证不可变归档、未修改文件、技能清单和私有启动器。打包启动与原生 Windows 检查验证生成资源，不发起付费请求。
